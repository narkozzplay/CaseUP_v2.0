# Сервер CaseUP: памятка

Короткая шпаргалка для ежедневной работы с сервером. Первичная установка — в [DEPLOY.md](DEPLOY.md).

| | |
|---|---|
| Сайт | https://case-up.ru, https://lib.case-up.ru |
| Сервер | `185.46.11.244` (Рег.облако, Ubuntu 24.04) |
| Папка проекта | `/opt/caseup` |
| Настройки | `/opt/caseup/.env.prod` |

> Пароли, ключи и содержимое `.env.prod` никому не присылайте и не показывайте на скриншотах.

---

## 1. Подключиться к серверу

На компьютере откройте **PowerShell** и выполните:

```powershell
ssh root@185.46.11.244
```

- Если спросит пароль — это пароль **root сервера** (из письма Рег.облака или тот, что вы задали командой `passwd`). При вводе символы не видны — это нормально. Вставка пароля — **правый клик** мышью.
- Подключились, когда видите строку вида `root@cv8143817:~#`.
- Выйти с сервера: `exit`.

### Вход без пароля (один раз)

В PowerShell **на компьютере** (не на сервере):

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@185.46.11.244 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

Пароль спросят последний раз, дальше `ssh root@185.46.11.244` будет входить сразу.

### Если ssh ругается `REMOTE HOST IDENTIFICATION HAS CHANGED`

Так бывает после переустановки сервера. В PowerShell на компьютере:

```powershell
ssh-keygen -R 185.46.11.244
```

и подключитесь заново (на вопрос ответьте `yes`).

## 2. Перейти в проект

Все команды ниже выполняются **на сервере** из папки проекта:

```bash
cd /opt/caseup
```

`dc` — это короткое имя для длинной команды
`docker compose --env-file .env.prod -f docker-compose.yml -f docker-compose.prod.yml`.
Если сервер отвечает `dc: command not found`, верните его:

```bash
echo "alias dc='docker compose --env-file .env.prod -f docker-compose.yml -f docker-compose.prod.yml'" >> ~/.bashrc
source ~/.bashrc
```

## 3. Обновить сайт

Когда в ветке `main` на GitHub появились изменения:

```bash
cd /opt/caseup
dc exec -T web python manage.py backup_db    # бэкап базы перед обновлением
git pull                                     # скачать новый код
dc up -d --build                             # пересобрать и перезапустить
docker image prune -f                        # удалить старые образы, чтобы не забивать диск
dc ps                                        # проверить, что всё запущено
```

- Сборка занимает 1–3 минуты, сайт недоступен примерно минуту.
- Миграции базы применяются автоматически при старте сайта.
- В `dc ps` у всех сервисов должно быть `Up` и `(healthy)` (у `caddy` — просто `Up`). Сразу после запуска может быть `(health: starting)` — подождите минуту и повторите `dc ps`.
- Откройте https://case-up.ru и убедитесь, что всё работает.

### Если `git pull` пишет про локальные изменения

Код на сервере руками не правится, поэтому такого быть не должно. Если всё же случилось — сбросить код к версии с GitHub (`.env.prod` и данные не затрагиваются):

```bash
git fetch origin && git reset --hard origin/main
```

### Откат на предыдущую версию

Если после обновления что-то сломалось:

```bash
git log --oneline -5                 # список последних версий, слева — их короткие номера
git checkout <номер-версии>          # например: git checkout eddec6a
dc up -d --build
```

Вернуться на актуальную версию: `git checkout main && git pull && dc up -d --build`.

> Если новая версия успела изменить базу (миграции), откат кода может не помочь — тогда восстановите бэкап, сделанный перед обновлением (раздел 7), или напишите разработчику.

## 4. Проверить состояние

```bash
dc ps                          # какие сервисы запущены и здоровы
dc logs --tail=100 web         # последние 100 строк логов сайта
dc logs -f web                 # логи в реальном времени (выход — Ctrl+C)
dc logs --tail=50 caddy        # HTTPS и входящие запросы
dc logs --tail=50 celery_worker
free -h                        # память
df -h /                        # место на диске
docker system df               # сколько места занимает Docker
```

Сервисы: `web` — сайт, `db` — база PostgreSQL, `redis` — очередь и кэш, `celery_worker` и `celery_beat` — фоновые задачи (сверка платежей, уведомления, очистка логов), `caddy` — HTTPS.

---

## 5. Перезапуск

```bash
dc restart web                 # перезапустить только сайт
dc up -d                       # поднять всё, что остановлено (безопасно запускать в любой момент)
reboot                         # перезагрузить сервер целиком; сайт поднимется сам через 1–2 минуты
```

## 6. Изменить настройки (`.env.prod`)

```bash
cd /opt/caseup
nano .env.prod                 # стрелки — перемещение, Ctrl+O, Enter — сохранить, Ctrl+X — выйти
dc up -d                       # пересоздать контейнеры с новыми настройками
```

Ключи Steam / FACEIT / Telegram удобнее менять в админке: **Control Center → Настройки → Интеграции** — там перезапуск не нужен.

## 7. Бэкапы

Создать бэкап вручную (база + загруженные файлы):

```bash
dc exec -T web python manage.py backup_db
```

Бэкапы лежат на сервере в `/var/lib/docker/volumes/caseup_prod_backup_data/_data`. Скачать их к себе — в PowerShell **на компьютере**:

```powershell
scp -r root@185.46.11.244:/var/lib/docker/volumes/caseup_prod_backup_data/_data $env:USERPROFILE\Documents\caseup-backups
```

Восстановление — только вместе с разработчиком: `dc exec web python manage.py restore_db --help`.

### Автоматический бэкап

Сайт сам делает бэкап каждую ночь в 04:15: база и загруженные файлы. На сервере копии хранятся 7 дней. Если настроен хостинг (раздел 7а), копия уходит туда и хранится 30 дней. Состояние видно в **Control Center → Система → «Резервные копии»**.

Сделать бэкап и отправить его на хостинг прямо сейчас:

```bash
dc exec web python manage.py backup_offsite --now
```

> Если раньше вы добавляли бэкап в `crontab -e` (по DEPLOY.md), удалите эти две строки (`crontab -e`, затем стереть строки с `backup_db` и `find … -mtime`): сайт теперь делает бэкап сам.

## 7а. Бэкапы на хостинг Рег.ру (SFTP)

Копия на другом сервере спасает данные, если с VPS что-то случится. Используем хостинг, где лежит почта.

**1. Включите SSH-доступ на хостинге.** Личный кабинет Рег.ру → **Хостинг** → ваш тариф → **Управление** / **Доступы**. Найдите раздел «SSH» и включите его. Там же указаны:
- **сервер** (адрес вида `serverXX.hosting.reg.ru` или IP);
- **логин** (вида `u1234567`);
- **пароль** (если не знаете — смените там же).

**2. Пропишите доступ в настройки сайта** (на сервере, `nano .env.prod`, в конец файла):

```bash
BACKUP_SFTP_HOST=serverXX.hosting.reg.ru
BACKUP_SFTP_USER=u1234567
BACKUP_SFTP_PASSWORD=пароль_от_хостинга
BACKUP_SFTP_PATH=caseup-backups
```

Папка `caseup-backups` создастся в домашнем каталоге хостинга — вне папки сайта, из интернета она недоступна.

**3. Примените и проверьте:**

```bash
dc up -d
dc exec web python manage.py backup_offsite --test     # должно быть: SFTP connection OK
dc exec web python manage.py backup_offsite --now      # первый бэкап сразу на хостинг
```

При первом подключении сайт запоминает ключ сервера хостинга. Если хостинг его сменит, бэкап остановится с понятной ошибкой — это защита от подмены сервера.

> Пароль хостинга храните только в `.env.prod` на сервере. Никому его не присылайте.

**Восстановление с хостинга** — только вместе с разработчиком: скачать папку бэкапа обратно на сервер и выполнить `restore_db`.

## 7б. Почта: письма об ошибках

Сайт присылает письмо, когда у посетителя происходит ошибка 500 (одна и та же ошибка — не чаще раза в 30 минут) и когда не удался ночной бэкап. Письма уходят с ящика `admin@case-up.ru` на хостинге.

**1. Узнайте адрес почтового сервера.** Панель хостинга → **Почта** → «Настройки почтового клиента» (или «Подключение к почте»). Нужен **SMTP-сервер**, порт **465 (SSL)**. Обычно это `mail.hosting.reg.ru`.

**2. Пропишите в `.env.prod`:**

```bash
EMAIL_HOST=mail.hosting.reg.ru
EMAIL_PORT=465
EMAIL_HOST_USER=admin@case-up.ru
EMAIL_HOST_PASSWORD=пароль_от_ящика_admin
DEFAULT_FROM_EMAIL=CaseUP <admin@case-up.ru>
ADMIN_EMAILS=admin@case-up.ru
```

В `ADMIN_EMAILS` можно указать несколько адресов через запятую, например и ваш личный.

**3. Примените и отправьте тестовое письмо:**

```bash
dc up -d
dc exec web python manage.py sendtestemail --admins
```

Письмо должно прийти на адреса из `ADMIN_EMAILS` (проверьте и «Спам»). В **Control Center → Система** строка «Почта» станет зелёной.

## 7в. Мониторинг: узнать о падении сайта раньше пользователей

Бесплатно, настраивается один раз, на сервере ничего делать не нужно.

1. Зарегистрируйтесь на **https://uptimerobot.com** (или в «Яндекс Мониторинге»).
2. **Add New Monitor** → тип **HTTP(s)**, адрес `https://case-up.ru/health/`, интервал 5 минут.
3. В «Alert Contacts» укажите почту (и при желании приложение на телефоне).

Если сайт перестанет отвечать, придёт письмо в течение 5 минут.

## 8. Один раз после установки

Ограничить размер логов Docker, чтобы они не заняли весь диск:

```bash
cat > /etc/docker/daemon.json <<'EOF'
{ "log-driver": "json-file", "log-opts": { "max-size": "10m", "max-file": "3" } }
EOF
systemctl restart docker
cd /opt/caseup && dc up -d --force-recreate
```

Обновления безопасности Ubuntu (раз в месяц):

```bash
apt update && apt -y upgrade
reboot                         # если после обновления написано "System restart required"
```


## 8б. Двухфакторная защита (2FA)

Подключается в профиле: **Настройки → Безопасность → Двухфакторная защита**. Нужно приложение-аутентификатор на телефоне (Google Authenticator, Яндекс Ключ, Microsoft Authenticator, Aegis).

- Для ролей **admin и выше** (и для superuser) 2FA обязательна: пока она не включена, сайт пускает только на страницу «Безопасность».
- После включения сайт один раз показывает **10 резервных кодов** — сохраните их в менеджере паролей или запишите. Каждый код срабатывает один раз вместо кода из приложения.
- Пользователю, который потерял телефон и коды, 2FA сбрасывает администратор: **Control Center → Пользователи → карточка → «Сбросить 2FA»**. Это попадает в журнал.

Если доступ потерял сам владелец сайта (телефон и резервные коды), сбросьте 2FA с сервера:

```bash
dc exec web python manage.py reset_2fa <логин>      # например: reset_2fa admin или reset_2fa steam_7656119...
```

После этого войдите на сайт и подключите 2FA заново.

## 8в. Рефералы и промокоды

- Рефералы пользователей и проверка подозрительных (общий IP) — **Control Center → Рефералы**. Пока реферал «на проверке», он не даёт скидок и бонусов.
- Промокоды создаются в **Control Center → Промокоды → «Новый промокод»**. У каждого кода — лимит активаций, срок и ограничения. Если указать блогера, новые аккаунты, активировавшие код, станут его рефералами.
- Засчитываются только реальные платежи. Пока касса ЮKassa в **тестовом режиме**, рефералы не засчитываются и бонус к пополнению не начисляется. Чтобы проверить это на тестовой кассе, добавьте в `.env.prod` строки и перезапустите (`dc up -d`), а после проверки уберите:

```bash
REFERRAL_COUNT_TEST_PAYMENTS=1
PROMO_COUNT_TEST_PAYMENTS=1
```

## 9. Если что-то не так

| Симптом | Что сделать |
|---|---|
| Сайт не открывается | `dc ps` — все ли сервисы `Up`. Если нет: `dc up -d`, затем `dc logs --tail=100 web`. |
| `502 Bad Gateway` | Сайт перезапускается или упал: подождите минуту, затем `dc logs --tail=100 web`. |
| Ошибка сертификата в браузере | `dc logs --tail=100 caddy`; проверьте, что DNS `case-up.ru` указывает на `185.46.11.244`. |
| `Bad Request (400)` | Домена нет в `DJANGO_ALLOWED_HOSTS` в `.env.prod`. |
| Не хватает места | `df -h /`, затем `docker image prune -f` и `docker builder prune -f`. |
| Сервис `unhealthy` | `dc logs --tail=100 <сервис>` — пришлите разработчику последние строки (без паролей). |
| Telegram «недоступен» | Telegram заблокирован в РФ — с российского сервера бот не работает, это ожидаемо. |
